# AI 陪伴引擎 · 参考实现

一个**能长期陪着人聊天**的 AI 角色引擎，纯前端、零构建、无后端。
这一份是可运行的参考实现：**重点不是"接个大模型"，而是"怎么让她像个人"**。

界面故意做成微信的样子（气泡、连发、时间分隔、正在输入），
因为要验证的东西只有当它看起来像"手机里一个真实的人"时才测得出来。

```
你说一句话
   │
   ├─ 记忆：她记得住吗？很久以前的事翻得出来吗？该忘的忘掉了吗？
   ├─ 时间：她知道现在几点、隔了多久、你说的"明天"还有多远吗？
   ├─ 关系：她认同自己的身份吗？会不会演着演着就串了？
   ├─ 情绪：她是暖的还是冷的？情绪有起伏吗？还是每句一个温度？
   └─ 边界：她不懂的东西会不会装懂？不懂你的事会不会连你一起推开？
```

---

## 一、这个引擎解决的具体问题

陪聊类应用最常被吐槽的不是"模型不够聪明"，而是下面这些**结构性毛病**。
每一条在这个仓库里都有对应的实现，也都有对应的测试。

| 毛病 | 症状 | 这里的做法 |
|---|---|---|
| **失忆** | "啊？你说过吗""我们才刚认识吧" | 记忆块放在提示词**最前面**（模型对开头最敏感）；关键词 IDF 检索翻出几百条以前的对话 |
| **记忆不真实** | 五年前的事连"她那天穿什么"都记得 | 遗忘曲线 + **纯细节封顶**：事情记得住，细节会模糊，而且要求她**照实说记不清、不许编** |
| **感情不升温** | 聊三个月还是陌生人语气 | 好感度分 5 档，每档写清"该怎么表现"；聊天微调（+0.4/句这种量级）；久不联系会淡 |
| **关系串味** | 设成"同事"却说着"想你" | 关系=**身份**（写死、不许动摇）／好感度=**温度**（会变），两个正交的轴 |
| **时间错乱** | 晚上十点说"明天下午送你",她急着催你快出发 | 注入虚拟时间；他说的时间词**先替她算好还剩多久**，明确写"现在还早，不用着急" |
| **人设漂移** | 20 岁设计生张口"我当年带团队做全案" | 知识储备按**年龄 + 职业**分档（学生版/工作版），12 个知识域 |
| **不懂装懂 / 冷场** | 要么硬答专业问题，要么一句"这我不懂"把人堵回去 | 同行才聊专业；不同行承认不懂**但必须带上跟情境相称的情绪**，并且 ⭐「不懂专业 ≠ 不懂他」 |
| **情绪平面** | 无论什么情况都是同一个温度 | 情绪强度 → 执念（≥7 分不受遗忘曲线影响）+ 情绪表达规则（开心的语气词怎么落字面上） |
| **应声虫** | "好的""我理解你的感受""你可以试试…" | 反顺从规则；共情优先于给建议；**人本主义三条件**（共情/真诚/积极关注） |
| **一上来就掏心掏肺** | 好感度这根轴完全没意义 | 积极关注**分档**：低好感是"有条件关注"（好是要挣的），高好感才是"无条件积极关注" |

> 这些不是"提示词里多写几句"能解决的，它们互相打架。
> 比如"关系写死"和"温度会变"就会冲突，所以必须先想清楚哪些是身份、哪些是温度。

## 二、架构：越往下越纯

**核心设计原则：`app.js` 以下的所有模块都不碰 DOM，也不碰全局状态。**
状态和副作用全部集中在最上面那一层 —— 这是它们能被单独 import 和测试的前提。

```
                        ┌──────────────────────────────────────────┐
                        │  app.js        状态 · 界面 · 事件 · 编排   │
                        │  （唯一持有 state，唯一碰 DOM）           │
                        └───────┬───────────────────────┬──────────┘
                                │                       │
        ┌───────────────────────┴──────┐        ┌───────┴────────────┐
        │  persona.js                  │        │  storage.js        │
        │  把下面这些拼成系统提示词      │        │  localStorage 读写  │
        │                              │        │  + 存盘前整理记忆   │
        └──┬────┬────┬────┬────┬───────┘        └───────┬────────────┘
           │    │    │    │    │                        │
           ▼    ▼    ▼    ▼    ▼                        ▼
    ┌──────────┐┌─────────┐┌──────────┐┌────────────┐┌──────────┐
    │zodiac.js ││affection││relation  ││profession  ││memory.js │
    │  星座     ││ 好感度  ││ 关系定位  ││ 职业知识    ││ 遗忘曲线  │
    └──────────┘└────┬────┘└────┬─────┘└────────────┘└────┬─────┘
                     │          ▼                         │
                     │   ┌────────────────┐               │
                     │   │relation-views  │               │
                     │   │ 关系视角文案    │               │
                     │   └────────────────┘               │
                     │                                    │
                     ▼                                    ▼
             ┌────────────────────────┐    ┌─────────────────────┐
             │  memory-io.js          │───▶│  recall.js          │
             │  记忆读写/检索/导入      │    │  2/3-gram + IDF     │
             └────────────────────────┘    └─────────────────────┘
                     ▲
             ┌───────┴────────┐
             │  emotion.js    │  情绪强度打分（≥7 = 执念）
             └────────────────┘

  另外几个谁都不依赖的小模块：
    format.js   文本格式化（HTML 转义闸门 / 时间显示 / 时长说法）
    search.js   搜聊天记录（纯子串，给人用的，和 recall.js 的模糊匹配相反）
    habits.js   相处习惯（反复做过的动作，别再给"第一次"的反应）
    api.js / providers.js / config.js
    native.js   手机本地推理桥接（只在安卓版里真正生效）
```

### 数据流

```
respond()
  ├─ 虚拟时钟算"现在几点"                    ← persona.describeTime
  ├─ 从旧记录里翻相关的话                     ← memory-io.recallOldMessages → recall.js
  ├─ 按遗忘曲线淘汰 + 钉住手动条目             ← storage.decayProfileFacts / hoistManualEntries
  ├─ 拼系统提示词                            ← persona.buildSystemPrompt
  │    ├─ 关于他的记忆 / 关系身份 / 此刻温度 / 人本主义
  │    ├─ 她懂什么（年龄+职业+同行判断）/ 星座 / 场景 / 相处习惯
  ├─ 发给模型（云端 api.js 或本地 native.js）
  ▼
她回了一段话
  ├─ 摘掉隐藏的 [[记忆]] 块                   ← memory-io.parseMemoryBlock
  ├─ 写进记忆 + 打情绪强度分                   ← memory-io.applyMemory（用 emotion.js）
  ├─ 好感度微调                              ← affection.drift
  └─ 存盘（先整理一遍）                       ← storage.saveProfile / writeChat
```

## 三、几个值得单说的设计取舍

### 1. 记忆为什么是"三层"，而不是一个数组

```
写入（memory-io.applyMemory）  一件事该不该记、记多重   ← 情绪强度打分
淡忘（memory.js + storage）    记下来之后会不会忘      ← 复习次数 / 半衰期
检索（memory-io + recall.js）  什么时候被想起来        ← 2/3-gram + IDF
```

分开是因为它们的**失效方式完全不同**：写入错了会记进假信息；
淡忘错了会"该忘的没忘"或"不该忘的忘了"；检索错了是"她明明知道却想不起来"。
混在一起时这三种 bug 长得一模一样，只能靠猜。

**纯细节封顶**是这里面最反直觉的一条：情绪强度再高，
只要条目里只有"几点""穿什么""在哪"，就**不给它执念资格** ——
让它像普通记忆一样淡掉。因为真人就是这样：事情记得，细节记不清。
而且明确要求她**照实说记不清，绝对不许编细节** ——
编出来的细节一旦对不上，比老实说"我忘了"更伤人。

### 2. 关系是身份，好感度是温度

一开始把两者写在同一段提示词里，结果它们**互相打架**：
好感度低时写"客气、有距离"，关系那块却写着"恋人"，模型直接演崩。

拆成正交的两个轴之后：
- **身份**写死、不许动摇（生气冷战也不降级，记录里有旧关系以最新为准）
- **温度**会变，但再低也不会低过身份（恋人冷淡 ≠ 恋人变陌生人）

"她认为我们的关系"这句话也是同理：原来 5 个通用模板套所有关系，
套到"夫妻"上会读出"你们早就不只是夫妻了"——**这句话本身就是错的**。
现在 15 种关系 × 5 个档位各写各的。

### 3. 人本主义：积极关注是**分档**的

罗杰斯的三个核心条件里，**共情**和**真诚**任何档位都成立（这是"像真人"的底线）。
但**积极关注**必须分档，否则好感度这根轴就没意义了：

| 好感度 | 积极关注 |
|---|---|
| < 40 | **有条件**：你的好是**要挣的**，他敷衍你就收回来 |
| 40–69 | 在变松，但还没打算惯着他 |
| ≥ 70 | **无条件**：不管他做了什么，都不否定他**这个人** |

写的时候最容易犯的错是**把低好感那档写暖** ——
那样她会一上来就掏心掏肺，整个好感度系统就白做了。

### 4. 虚拟时钟：她感知的"现在"不跟现实走

```js
const now = () => Date.now() + (Number(state.config.clockOffset) || 0);
```

全系统（时间描述、场景演变、消息时间戳、记忆衰减）都用这一个 `now()`。
看一场两小时的电影就点「+2 小时」，她就**真的觉得过了两小时**；
也可以直接选"跳到某年某月某日几点"。

配套的坑：**拨时间不许重画整个聊天区**（聊到几百条时那一步肉眼可见地卡），
只刷新时钟文字和时间分隔条的文案 —— 测试里直接断言
"拨完之后聊天区的 DOM 节点还是同一个"。

### 5. 她懂什么，跟年龄和职业一起定

只写一句"你是学视觉传达的大二学生"是不够的：她一聊到画图就会冒出
职业设计师的口气（"我当年带团队做全案"），人设当场就假了。

所以知识储备按 **12 个知识域 × 学生版/工作版** 给，
年龄只用来在两者之间选（20 岁的程序员也算工作版）。

**同行 / 不同行**是另一个轴：
- 同行 → 能聊到一块去（吐槽 / 请教 / 有点小较劲三种自然反应）
- 不同行 → 只聊自己那摊，承认不懂

这一块最容易做坏成"不懂你的专业 = 不懂你"，
所以里面明确写了：情绪要跟情境相称（他兴奋→好奇、抱怨→共情、
泄气→**不夸他的专业，夸他这个人**、较真→自嘲），
⭐「不懂专业不等于不懂他」，而且**不许每句都"我不懂"**。

### 6. 检索式记忆为什么不用向量

手机端跑 embedding 要额外下模型、额外算力。
2/3-gram + IDF 这一档对"做饭""加班""猫""项目"这类具体话题已经够用，
而且**零成本、零依赖**。中文不用词典也能切。

代价是**单个汉字搜不出来**（2-gram 起步）—— 这是刻意的取舍，写在代码注释里了。

## 四、跑起来

```bash
npm install        # 只为测试装 jsdom，运行时零依赖
npm run dev        # → http://localhost:8090
```

打开后：设置里选模型服务商（任何 OpenAI 兼容接口都行）→ 填 API Key → 开始聊。
Key 只存在你自己的浏览器 localStorage 里，不会上传到任何地方。

想完全离线：安卓版可以把 llama.cpp 放进手机里跑（`src/native.js` 是桥接层，
需要自己配 Capacitor 工程）。

### 测试是怎么跑起来的

`boot.mjs` + `inline.mjs` 把前端模块**内联进 jsdom**，并注入真实的 `styles.css` ——
不注入的话 `getComputedStyle` 只能看到浏览器默认样式，
"被 `hidden` 的元素是不是真的看不见"这类断言全是假绿。

`test-modules.mjs` 是另一层：它在 **node 里（没有 DOM）直接 import 四个模块**。
这是"真的解耦了"的唯一硬证据 —— 只经过 `app.js` 的话，
模块里偷偷用了全局 `state` 或 `document` 也发现不了。

```bash
npm run cc         # 圈复杂度分析（自己实现的，零依赖）
```

## 六、可以拿去改的地方

- **换人设**：`src/persona.js` 的 `CHARACTER` + `TRAIT_PRESETS`，或直接用人设页
- **换关系种类**：`src/relation.js` 的 `RELATIONS`（15 种）+ `relation-views.js` 的文案
- **换知识域**：`src/profession.js` 的 `DOMAINS`（12 个领域 × 两套说法）
- **换遗忘策略**：`src/memory.js` 的 `halfLifeDays` / `permanentReason`
- **换情绪词表**：`src/emotion.js` 的 `TIERS`
- **接别的模型**：`src/providers.js` 加一条，或直接在设置里填 OpenAI 兼容地址
